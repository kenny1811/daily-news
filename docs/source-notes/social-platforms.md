# Threads、Facebook、Instagram 來源操作

Kenny 2026-10-11 批准加入來源池。呢份係編採流程，唔係三個平台嘅可用性測試結果。每次用原帖都要重新核實；規矩以 AGENTS.md 第 7、9、10、11 節及 tools/rules.json 為準。

## 搜料與採用

**Threads 搜料對象（2026-10-13 am 起）**：唔搵新聞池已有嘅傳媒帳戶填 Threads 目標，要搵散戶第一手原帖。先用事件名、地點、生活情況、行業問題等關鍵詞搜尋，唔以現有媒體 handle 作預設入口；沿合格原帖嘅相關討論追尋最初當事人或目擊者。優先核對現場目擊者、受影響市民、從業者及獨立個人，記錄佢與事件嘅實際關係。傳媒可用作交叉查證，唔用佢嘅 Threads 連結冒充散戶原帖。

採用前要分清原創第一手見聞、個人聲稱、評論同轉貼。純轉貼新聞或冇新增原始資料嘅評論唔當第一手新聞；原有純娛樂／KOL限制照守。核實紀錄加作者類型、事件關係、第一手內容、身份依據及交叉核實結果。selfcheck 嘅平台 URL 計數唔能夠證明作者係散戶，呢項必須人手覆核；缺料報實際差額，唔用傳媒帳戶補數。

**現行流程（Kenny 特批追溯 2026-10-13 pm，並准只限該版過死線補稿）**：只搜及採用 Threads 社交原帖，唔搜或採用 Facebook、Instagram。由 13 日 pm 起，每組新聞卡同每篇簡報以至少50%合格 Threads 原帖為搜料目標，奇數向上取整；差額唔令自檢失敗，仍要喺當版簡報逐組／逐篇寫「實際採用／目標／差額」及主要排除原因。零帖要寫 0，唔好用傳媒帳戶、轉載或無原始資訊評論湊數。其餘時間、圖片、禁用來源、媒體數規矩仍係硬要求；13 日 am 及之前版唔追溯改。**

**遲報新聞與較早原帖（由 2026-10-14 am 起）**：先確定單篇新聞報道喺本版時間窗內首次發佈，並確實首次披露或核實較早散戶 Threads 原帖涉及嘅事；再讀原帖全文、作者、首發時間及原圖。原帖可早過時間窗，但第 5／6 欄照填原帖真實時間，第 9 欄 `freshReport` 寫窗內新報道來源、單篇 URL、首發時間與新增資訊。兩條連結都顯示畀讀者；只係轉載舊帖、冇新報道或冇直接關係，不計入 Threads 配額。不得將新報道時間填入原帖發放欄。既有歷史版規則不變。

2026-10-12 更新（當晚 pm 起）：每個新聞組至少50%卡直接連合格社交原帖，奇數向上取整；原8條要4條、原3條要2條，條數不增加。全版新聞卡須同時有Threads、Facebook、IG，毋須每組齊三平台。AI及戰爭簡報各自至少50%採用來源為原帖；原4／3來源各要2條。已發布版不追溯。先搜社交候選、預留各組配額，再補網站來源，採用連結才算，線索及交叉查核不算。selfcheck按 tools/rules.json social 強制驗證。

同一事件跨平台只留一條、同一作者只算一個機構；不能把重複轉帖湊成不同新聞。來源名仍用實際作者／機構，不以平台名冒充作者。目標不足須記錄每組及每篇簡報實際採用／目標／差額、已開原帖及主要排除原因，不能只講「已搜尋」。圖片、身份、首次時間與爭議歸屬照原規則核實；夜報其他硬規矩不過自檢仍不定稿。

1. 每次出稿按各組題材、熱度關鍵詞及現有 track 搜相關公開原帖，可由平台搜尋、搜尋引擎或原作者網站連結進入。沒有合格結果就記錄，唔為湊條數拖延。
2. 打開原帖，讀全文、上下文、更正及引用來源；影片要實際查看與採用內容有關嘅片段，唔單憑縮圖或標題。轉載及截圖追返最初發帖者，核對事發日期與發帖日期，避免舊片當新事。
3. 核對作者／機構身份與關係，例如其網站互相連結、過往公開活動及其他可信報道；唔單憑顯示名、頭像或認證標記。匿名爆料先當線索，有足夠佐證先報；重大指控及爭議交叉查證，文字保留來源歸屬。
4. 記錄單一原帖永久連結及 post ID，唔用帳戶首頁、搜尋頁或短連結作最終卡連結。卡來源名用實際作者／機構嘅一致名稱；平台、帳戶 handle 及身份核對方法放核實紀錄。
5. 從原帖 metadata 或可核對嘅完整時間讀首次發放及更新時間，記錄原值、時區、HKT 換算與查核時間。轉發／重新上載唔把已出過嘅同一事件變成新進展；只有相對日期而無法確定窗內，就不用作直接卡來源。
6. 直接卡圖片仍取原帖實際 `og:image`，逐字比對後讀取圖片，保留 HTTP status、MIME、bytes、magic、實際解碼及目視結果。通用 logo、登入頁預覽或無關縮圖不合格；不能用截圖或自行拼 CDN 連結代替。影片帖如果無合格 OG 圖，只作線索另找報道。
7. 原帖可讀、身份與內容核實、時間窗及圖片合格，先按既有 JSON 格式入卡；讀唔到或不合格就找可核實傳媒報道，卡連結及時間用實際採用嗰篇，原帖留作背景證據。

## 來源限制及計數

- 原有禁用來源及政府／官媒限制跟機構走，換到社交平台都一樣；hke 額外禁用亦一樣。
- 同一機構網站與三個平台只算一個來源；同一事件跨平台去重，唔靠改來源名湊多樣性。
- 簡報最少媒體數仍要由實際不同媒體滿足，個人／企業自述可作額外原始來源，唔冒充新聞媒體。
- hke 合資格獨立來源仍依 tools/rules.json 清單；核對帳戶確屬該媒體，保留原有一致媒體名，不把平台本身當獨立媒體。
- 登入牆、封鎖、刪帖或內容不足要如實記錄；唔要求用戶提供私人帳戶，唔繞過存取限制。回退至其他可核實來源。

## 核實紀錄最少包含

平台、作者／機構與 handle、post ID／永久連結、身份核對依據、原帖內容／引用來源、首發及更新原值與時區、HKT 時間、真實查核時間、交叉查證及矛盾裁決、OG 比對與圖片驗證結果、採用或排除原因。依既有 scratch、當版核實證據及簡報紀錄保存。
