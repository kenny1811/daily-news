# 來源勘測報告 2026-09-19（星期六）

實測時間 10:31–10:58 HKT，三個勘測 agent 並行，共試 41 個候選。方法：`curl -sL --compressed -A "Mozilla/5.0"` 三層驗（首頁／RSS／單篇），時區一律用 wp-json `date`／`date_gmt`、RSS `pubDate`、JSON-LD 三重交叉核對，唔信 offset 標籤。

## 一、最重要嘅三項更正（舊規矩寫錯）

1. **經濟一週 edigest**：`article:published_time` 個 `+00:00` **係假標籤，數值本身已經係 HKT，唔使換算**。實測 post 2041124：wp-json `date`＝`09-19T09:21:11`、`date_gmt`＝`09-19T01:21:11`、meta＝`09-19T09:21:11+00:00`（逐秒等於 `date`）。照舊規矩 +8 會令每張 edigest 卡遲 8 個鐘、直接衝爆時間窗。
   另外「週末停更」都係錯：星期六實測 10:33 前已出 21 篇，上星期六 27 篇。
2. **Mingtiandi**：同一個 Yoast 假 `+00:00` 陷阱，`article:published_time` 係 HKT 唔使換算，**反而 JSON-LD `datePublished` 先係真 UTC 要 +8**。兩個欄位差足 8 個鐘。
3. **The Standard**：有 JSON-LD `"datePublished":"…+0800"`，本身就係 HKT。舊規矩「單篇冇時間 meta、要用 N mins ago 推算」已作廢。

## 二、通用法則（已入 CLAUDE.md 第 7 節）

WordPress／Yoast 嘅 `article:published_time` 個 `+00:00` 唔可信，同一個 CMS 兩種行為都有：

| 站 | meta 值實際等於 | 要唔要 +8 |
|---|---|---|
| Dimsum Daily、Asia Times、Asia Financial | `date_gmt`（真 UTC） | 要 +8 |
| edigest、Mingtiandi | `date`（本地 HKT） | 唔使 |

→ 任何 WP 來源第一次用之前行一次 `https://<站>/wp-json/wp/v2/posts?per_page=5&_fields=date,date_gmt,link`。呢條 curl 同時係查日產量／週末凌晨有冇稿最快嘅方法。

## 五、新發現嘅 fatal 級伏位

1. **The Standard 全站任何路徑都回 HTTP 200**（連亂打 ID、`/rss`、`/sitemap.xml` 都係）→ HTTP code 完全唔可以做存在性檢查，一定要睇有冇 `og:title` ＋ `datePublished`。
2. **`image.hkstandard.com.hk` 錯 hash 一樣回 200**（同 `image.hkhl.hk` 一樣係星島系）→ 第 9 節第二步驗圖對佢無效，只可以靠第一步逐字比對。
3. **i-CABLE 單篇未 encode 嘅中文 slug curl 回 404**，要由首頁抄返完整 percent-encoded URL（當日午報兩條都中招）。
4. **法庭線 encoded 中文 slug 斬短一個字就 400**。
5. **Dimsum Daily 部分 slug 含 `%e2%80%91` 特殊連字號**，唔准手改做普通 `-`。
6. **hk01 單篇 meta 係 `content` 排喺 `property` 前面**，grep 唔可以淨係由 `property="og:image"` 開頭配。
7. **Dimsum Daily 同頁另有個 `itemprop="datePublished"` 係 HKT 錯標**，只可以信 `<meta property="article:published_time">`。
